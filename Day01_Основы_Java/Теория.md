## 0. Общая картина: что происходит, когда ты запускаешь Java-программу

Прежде чем нырять в детали, посмотрим на путь «от текста до результата». Это как путешествие письма:

```
Ты написал текст          Почтальон упаковал       Получатель прочитал
  Main.java      --javac-->   Main.class      --java-->  JVM исполняет
 (исходник)                (байт-код)                  (машинный код)
```

1. Ты пишешь исходник `Main.java` — обычный текст, понятный человеку.
2. Компилятор `javac` переводит его в **байт-код** `Main.class` — «универсальный язык» JVM.
3. JVM загружает байт-код, проверяет его и исполняет: сначала интерпретирует, потом компилирует «горячие» места в машинный код конкретной ОС.

Ключевая идея: **байт-код не привязан к процессору и операционной системе**. Именно поэтому Java работает по принципу WORA (Write Once, Run Anywhere) — «написал один раз, запускай где угодно».

Аналогия: байт-код — это как язык жестов. Ты объясняешь что-то одними жестами, а переводчик (JVM) рядом с каждым зрителем переводит их на его родной язык (Windows, Linux, macOS).

## 1. JVM, JRE, JDK: что это, кто кого включает

### 1.1 Матрёшка из трёх понятий

Три компонента образуют «матрёшку»:

```
JDK  ⊃  JRE  ⊃  JVM
```

Читается так: **JDK включает в себя JRE, а JRE включает в себя JVM**. Чем больше слой, тем больше возможностей.

| Слой | Полное название | Что внутри | Кому нужно |
|---|---|---|---|
| **JVM** | Java Virtual Machine | Машина исполнения байт-кода | Всем, кто запускает Java |
| **JRE** | Java Runtime Environment | JVM + стандартная библиотека классов | Тем, кто только **запускает** готовые программы |
| **JDK** | Java Development Kit | JRE + инструменты разработчика (javac, jar, javadoc…) | Тем, кто **пишет** код |

Аналогия: JVM — это двигатель автомобиля. JRE — это автомобиль целиком (двигатель + кузов + колёса), на нём можно ехать. JDK — это автомобиль **плюс гараж с инструментами и запчастями**, чтобы этот автомобиль собирать и ремонтировать.

### 1.2 JVM (Java Virtual Machine)

**JVM** — ядро платформы. Это **абстрактная вычислительная машина** со своим набором команд (байт-код), своим стеком, кучей и системой исполнения.

Что делает JVM:
- **загружает** `.class`-файлы (через ClassLoader);
- **верифицирует** байт-код (Bytecode Verifier — проверяет, что код не делает опасных вещей);
- **интерпретирует** и/или **JIT-компилирует** байт-код в машинные инструкции конкретной ОС;
- **управляет памятью** (Garbage Collection — автоматическая уборка мусора);
- обеспечивает принцип **WORA** (Write Once, Run Anywhere).

### 1.3 JVM — это спецификация, а не программа

Очень важный момент, который любят спрашивать:

> **JVM — это СПЕЦИФИКАЦИЯ** (документ с правилами), а не конкретная программа. Есть официальный документ «The Java Virtual Machine Specification», где описано, как должна вести себя любая JVM. А конкретных **реализаций** много.

Представь: «автомобиль» — это спецификация (должен быть двигатель, колёса, руль). А конкретные марки — реализации.

### 1.4 Реализации JVM

| Реализация | Кто делает | Особенности |
|---|---|---|
| **HotSpot** | Oracle / OpenJDK | Стандарт де-факто, входит в обычный JDK. Умный JIT (C1/C2) |
| **OpenJ9** | IBM / Eclipse | Экономичнее по памяти, быстрый старт. Часто в облаках |
| **GraalVM** | Oracle Labs | Поддержка многих языков, Native Image (AOT-компиляция) |
| **ART** | Google (Android) | Формально не JVM, но родственна (Android Runtime) |
| **Azul Zulu / Zing** | Azul | Низкие паузы GC, большие кучи |

В 99% случаев на собеседовании и в работе ты имеешь дело с **HotSpot** — он стоит «по умолчанию».

### 1.5 JRE (Java Runtime Environment)

**JRE** = JVM + стандартная библиотека классов (JCL — Java Class Library): `java.lang`, `java.util`, `java.io`, `java.net` и так далее.

Зачем нужна: чтобы **запускать** готовые приложения. Внутри **нет** компилятора и инструментов разработки.

> Начиная с Java 9 отдельный JRE как поставка практически исчез. Вместо него — **модульный образ**, который собирается инструментом `jlink` (только нужные модули). Поэтому сегодня обычно пишут «JRE = JVM + библиотеки», но физически ты скачиваешь JDK.

### 1.6 JDK (Java Development Kit)

**JDK** = JRE + инструменты разработчика:

- `javac` — компилятор (`.java` → `.class`);
- `jar` — упаковщик классов в архив `.jar`;
- `javadoc` — генератор документации из комментариев;
- `jdb` — отладчик;
- `jconsole`, `jvisualvm`, `jmap`, `jstack`, `jcmd` — диагностика;
- `jlink` — сборка своего runtime-образа (Java 9+);
- `jpackage` — упаковка в нативный установщик (Java 14+);
- `jshell` — интерактивная оболочка (Java 9+).

### 1.7 Как всё взаимодействует (полная схема)

```
Main.java  --javac-->  Main.class (байт-код)
                            |
                            v
              JRE: загрузка классов (ClassLoader)
                            |
                            v
     JVM: Bytecode Verifier -> Interpreter/JIT -> машинный код ОС
                            |
                            v
                    Результат работы программы
```

Важно: байт-код **не привязан** к конкретному процессору. Переносимость обеспечивается тем, что **для каждой ОС существует своя реализация JVM**. Один и тот же `Main.class` побежит и на Windows, и на Linux, и на macOS — если там стоит подходящая JVM.

### 1.8 Типичные ошибки раздела

- **Ошибка:** «JVM — это программа, которую устанавливают». На самом деле JVM — спецификация; устанавливают **JDK/JRE**, внутри которого конкретная реализация (HotSpot).
- **Ошибка:** путать JRE и JDK. Запускать программу можно и на JRE, а **компилировать** — только на JDK.
- **Ошибка:** думать, что байт-код — это машинный код. Нет, это промежуточный формат для JVM.

### 1.9 Часто спрашивают на собеседовании

**Вопрос:** Что такое JVM, JRE, JDK? Кто кого включает?
**Ответ:** JVM — виртуальная машина, исполняющая байт-код. JRE = JVM + стандартная библиотека (для запуска). JDK = JRE + инструменты разработчика (для написания). Иерархия: JDK ⊃ JRE ⊃ JVM.

**Вопрос:** JVM — спецификация или реализация?
**Ответ:** Спецификация. Реализации: HotSpot, OpenJ9, GraalVM, ART.

**Вопрос:** Что такое WORA?
**Ответ:** Write Once, Run Anywhere — один байт-код исполняется на любой ОС, где есть JVM.

## 2. Компиляция и запуск из консоли

### 2.1 Класс без пакета

Создай файл `Main.java`:

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("Привет, Java!");
    }
}
```

Компиляция и запуск:

```bash
javac Main.java     # появляется Main.class рядом с исходником
java Main           # указывается ИМЯ КЛАССА, а не имя файла
```

Ожидаемый вывод:

```
Привет, Java!
```

> **Запомни навсегда:** команде `java` передаётся **имя класса**, а не имя файла. `java Main.class` — ошибка, потому что JVM будет искать класс с буквальным именем `Main.class`.

Аналогия: `javac` — это переводчик, который сделал перевод книги (`Main.class`). А `java Main` — это команда «прочитай мне книгу под названием Main», а не «прочитай файл Main.class».

### 2.2 Класс в пакете

Пусть структура такая: файл лежит в `com/example/Main.java`, а первая строка файла:

```java
package com.example;

public class Main {
    public static void main(String[] args) {
        System.out.println("Я в пакете com.example");
    }
}
```

Компиляция с флагом `-d`:

```bash
javac -d . com/example/Main.java
```

Флаг `-d .` означает: «создай структуру папок пакета относительно текущей директории (`.` = текущая папка)». После компиляции появится `./com/example/Main.class`.

Запуск:

```bash
java com.example.Main    # полностью квалифицированное имя (FQN)
```

Ожидаемый вывод:

```
Я в пакете com.example
```

> **Правило:** запуск всегда выполняется из **корня проекта** — там, где начинается дерево пакетов (там, где лежит папка `com`). Если запустить из `com/example`, JVM не найдёт класс.

### 2.3 Почему `java Main.class` — ошибка

```bash
java Main.class
```

JVM попытается найти класс с именем `Main.class` (буквально, с точкой и словом class). Не найдёт → получишь:

```
Error: Could not find or load main class Main.class
Caused by: java.lang.ClassNotFoundException: Main.class
```

### 2.4 Запуск одного файла (Java 11+)

Начиная с Java 11 можно запускать исходник **напрямую**:

```bash
java Main.java
```

JVM сама компилирует код в память и сразу запускает его, **не создавая `.class` на диске**. Удобно для маленьких скриптов и обучения, но не для больших проектов.

### 2.5 Classpath (путь поиска классов)

**Classpath** — это список мест, где JVM ищет `.class`-файлы и `.jar`-архивы. По умолчанию — текущая директория (`.`).

```bash
# указать явно
java -cp . Main
java -classpath . Main

# несколько путей (разделитель в Windows — ;, в Linux/macOS — :)
java -cp ".;lib/mylib.jar" com.example.Main
java -cp ".:lib/mylib.jar" com.example.Main

# можно через переменную окружения
set CLASSPATH=. (Windows)
export CLASSPATH=. (Linux/macOS)
```

Если класс не найден, чаще всего проблема именно в classpath: JVM ищет не там, где он лежит.

### 2.6 Полезные флаги javac и java

| Флаг | Где | Что делает |
|---|---|---|
| `-d <dir>` | javac | Куда положить скомпилированные `.class` (с учётом пакетов) |
| `-cp`, `-classpath` | javac/java | Пути поиска классов и jar |
| `-sourcepath` | javac | Где искать исходники зависимостей |
| `-source` / `-target` | javac | Версия языка / версия байт-кода |
| `--release N` | javac | Компилировать под конкретную версию (заменяет source+target) |
| `-Xss`, `-Xmx` | java | Размер стека / максимальный размер кучи |
| `--enable-preview` | javac/java | Включить preview-фичи (экспериментальные) |
| `-jar` | java | Запустить исполняемый jar (`java -jar app.jar`) |
| `-verbose:class` | java | Показать, какие классы загружаются |

### 2.7 Типичные ошибки компиляции и запуска

| Ошибка | Когда возникает | Причина |
|---|---|---|
| `ClassNotFoundException` | `java Main.class`, неверный classpath | JVM не нашла класс в момент загрузки |
| `NoClassDefFoundError` | Класс был при компиляции, но пропал в рантайме | Ошибка инициализации/отсутствие зависимости |
| `NoSuchMethodError` | Запуск с несовместимой версией библиотеки | В классе нет ожидаемого метода (например, `main`) |
| `Could not find or load main class` | Неверное имя или classpath | Класс не найден или нет `main` |
| `error: file not found: X.java` | Опечатка в пути | Файл отсутствует |
| `class X is public, should be declared in a file named X.java` | Имя файла ≠ имя public-класса | Java требует совпадения |

Разберём разницу между тремя «похожими» ошибками:

- **`ClassNotFoundException`** — **checked** исключение. Возникает, когда класс ищут **явно** через рефлексию/`Class.forName`/ClassLoader и не находят.
- **`NoClassDefFoundError`** — **Error**. Класс существовал при компиляции, но в рантайме его нет **или** он не смог инициализироваться (упал static-блок).
- **`NoSuchMethodError`** — **Error**. Класс найден, но нужного метода в нём нет (классика «версионного конфликта»: скомпилировали против одной версии библиотеки, запустили с другой).

### 2.8 Часто спрашивают на собеседовании

**Вопрос:** Зачем флаг `-d`?
**Ответ:** Он раскладывает `.class` по структуре пакета (например, `com/example/Main.class`), иначе JVM не найдёт класс по имени пакета.

**Вопрос:** Почему `java Main.class` — ошибка?
**Ответ:** `java` принимает имя класса, а не файл. Будет искать класс `Main.class`.

**Вопрос:** Что делает `java Main.java` (Java 11+)?
**Ответ:** Компилирует исходник в память и сразу запускает, без создания `.class` на диске.

**Вопрос:** Чем `ClassNotFoundException` отличается от `NoClassDefFoundError`?
**Ответ:** Первое — checked-исключение при явном поиске класса; второе — Error, класс был доступен при компиляции, но отсутствует/не инициализировался в рантайме.

## 3. JIT-компилятор

### 3.1 Проблема: интерпретация медленная

Изначально JVM **интерпретирует** байт-код: каждая инструкция переводится в машинную и исполняется **по одной**. Это быстро стартует (не надо ничего компилировать заранее), но **медленно работает** — как чтение вслух по слогам.

Аналогия: представь, что ты читаешь текст на иностранном языке через переводчика. Он переводит каждое предложение по очереди. Работает, но медленно. А JIT — это если переводчик заметит, что ты читаешь один и тот же абзац сотый раз, и один раз переведёт его начисто, а дальше ты просто читаешь готовый перевод.

### 3.2 JIT (Just-In-Time) — компиляция «на лету»

JIT исправляет медленную интерпретацию:

1. **Профилирование.** JVM собирает статистику: сколько раз вызывается метод, сколько итераций проходит цикл. Находит **«горячие точки» (hot spots)**.
2. **Компиляция.** Когда счётчик превышает порог, метод компилируется **целиком** в оптимизированный машинный код и кладётся в **Code Cache**.
3. **Подмена.** При следующем вызове исполняется уже нативный код — ускорение в десятки раз.

### 3.3 Code Cache

**Code Cache** — область памяти, где хранится скомпилированный JIT-ом машинный код. Настраивается флагами (например, `-XX:ReservedCodeCacheSize`). Если Code Cache переполнится, JIT перестанет компилировать новые методы — программа продолжит работать, но медленнее.

### 3.4 Tiered Compilation (многоуровневая компиляция)

В HotSpot по умолчанию включена **Tiered Compilation** — «лестница» из уровней:

| Компилятор | Уровень | Скорость компиляции | Качество кода | Роль |
|---|---|---|---|---|
| **C1 (Client)** | 1–3 | Быстро | Базовые оптимизации | Быстрый «прогрев», снижает старт |
| **C2 (Server)** | 4 | Медленно | Агрессивные оптимизации | Максимальная скорость hot spots |

Идея: сначала метод компилируется **C1** (быстро, чтобы сразу ускорить), а если он окажется действительно горячим — перекомпилируется **C2** (умно, максимально быстро).

### 3.5 Оптимизации JIT (что именно делает C2)

- **Inlining (инлайнинг)** — встраивание тела маленького метода прямо в место вызова. Убирает накладные расходы на вызов метода и открывает другие оптимизации.
- **Loop unrolling (разворачивание циклов)** — тело цикла повторяется несколько раз подряд, чтобы уменьшить количество проверок условия.
- **Escape Analysis (анализ «убегания»)** — если объект не «убегает» за пределы метода, его можно разместить **на стеке** вместо кучи (или вообще разобрать на скаляры — **Scalar Replacement**). Это снижает нагрузку на GC.
- **Lock elision (устранение блокировок)** — если блокировка не нужна (объект не шарится между потоками), её убирают.
- **Devirtualization (девиртуализация)** — если известно, что реализация метода одна, вызов делают прямым.
- **Dead code elimination** — удаление недостижимого кода.
- **Constant folding** — вычисление константных выражений на этапе компиляции (`2 * 3` → `6`).
- **Null-check elimination** — удаление лишних проверок на `null`.

### 3.6 Escape Analysis — пример

```java
public class EscapeDemo {
    static class Point {
        int x, y;
        Point(int x, int y) { this.x = x; this.y = y; }
    }

    // Объект Point НЕ возвращается и НЕ сохраняется в поле ->
    // он "не убегает". JIT может разместить его на стеке, не трогая Heap.
    static int sum() {
        Point p = new Point(1, 2);
        return p.x + p.y;
    }

    public static void main(String[] args) {
        long s = 0;
        for (int i = 0; i < 100_000_000; i++) {
            s += sum();
        }
        System.out.println(s); // 300000000
    }
}
```

Комментарий: на первых итерациях объект честно создаётся в куче, но после «прогрева» JIT применяет Escape Analysis и Scalar Replacement — аллокации исчезают, а `sum()` становится почти бесплатной.

### 3.7 Деоптимизация (deoptimization)

JIT строит оптимизации на **предположениях**. Если предположение перестало выполняться — код **откатывают** к интерпретируемой/менее оптимизированной версии. Это и есть **деоптимизация**.

Пример: JIT увидел, что в коде всегда вызывается `Cat.sound()`, и заинлайнил его. Потом загрузился новый класс `Dog extends Animal`, и вызов стал полиморфным — оптимизация невалидна, JVM деоптимизирует метод и перекомпилирует.

> Деоптимизация — **не ошибка**, а нормальный механизм корректности. Частые деоптимизации могут снижать производительность, поэтому важно, чтобы код был «предсказуемым» для JIT.

### 3.8 AOT и GraalVM Native Image

- **AOT (Ahead-Of-Time)** — компиляция **заранее**, до запуска.
- **GraalVM Native Image** — компилирует Java-приложение в **нативный исполняемый файл** (как `.exe`). Плюсы: мгновенный старт, меньше памяти. Минусы: долгая сборка, нет полноценных динамических JIT-оптимизаций, ограничения на рефлексию (нужна конфигурация).

| Критерий | JIT (HotSpot) | AOT (Native Image) |
|---|---|---|
| Старт | Медленнее (прогрев) | Мгновенный |
| Пиковая скорость | Выше (динамические оптимизации) | Ниже |
| Память | Больше | Меньше |
| Рефлексия | Полная | Ограничена (нужна настройка) |

### 3.9 Типичные ошибки раздела

- **Ошибка:** думать, что JIT компилирует **весь** код сразу. Нет — только hot spots, постепенно.
- **Ошибка:** путать JIT и AOT. JIT — во время работы, AOT — заранее.
- **Ошибка:** считать деоптимизацию багом.

### 3.10 Часто спрашивают на собеседовании

**Вопрос:** Зачем JIT, если есть интерпретатор?
**Ответ:** Интерпретатор быстрый на старте, но медленный в цикле. JIT компилирует горячий код в машинный и ускоряет его в десятки раз.

**Вопрос:** Что такое hot spots и Code Cache?
**Ответ:** Hot spots — часто исполняемые участки кода. Code Cache — область памяти со скомпилированным JIT-машинным кодом.

**Вопрос:** Разница C1 и C2?
**Ответ:** C1 компилирует быстро с базовыми оптимизациями (прогрев), C2 — медленно, но агрессивно оптимизирует (пиковая скорость). Tiered Compilation использует оба.

**Вопрос:** Что такое Escape Analysis?
**Ответ:** Анализ, «убегает» ли объект из метода. Если нет — его можно положить на стек вместо кучи, снизив нагрузку на GC.

**Вопрос:** Что такое деоптимизация?
**Ответ:** Откат оптимизированного кода, когда предположения JIT перестали выполняться (например, появился новый наследник).

## 4. Области памяти JVM

Память JVM делится на **поток-локальную** (у каждого потока своя) и **разделяемую** (общая для всех).

| Область | Тип | Что хранит |
|---|---|---|
| Stack | Поток-локальная | Фреймы методов, локальные переменные, ссылки |
| PC Register | Поток-локальная | Адрес текущей инструкции |
| Native Method Stack | Поток-локальная | Вызовы нативных (JNI) методов |
| Heap | Разделяемая | Все объекты и массивы |
| Metaspace | Разделяемая | Метаданные классов |
| Code Cache | Разделяемая | JIT-машинный код |
| Direct Memory | Разделяемая (off-heap) | Прямые буферы |

### 4.1 Stack (стек) — на каждый поток

- Работает по принципу **LIFO** (Last In, First Out) — как стопка тарелок.
- Каждому вызову метода соответствует **фрейм (Stack Frame)**.
- Во фрейме: локальные примитивы, ссылки на объекты, операнд-стек, ссылка на пул констант.
- Быстро, освобождается **автоматически** при выходе из метода.
- Размер задаётся флагом `-Xss` (например, `-Xss1m`).
- Переполнение → **`StackOverflowError`** (классика — глубокая/бесконечная рекурсия).

```java
public class StackDemo {
    static int depth = 0;

    static void recurse() {
        depth++;
        recurse(); // бесконечная рекурсия
    }

    public static void main(String[] args) {
        try {
            recurse();
        } catch (StackOverflowError e) {
            System.out.println("Глубина: " + depth);
            // Глубина: ~10000-20000 (зависит от -Xss)
        }
    }
}
```

### 4.2 Heap (куча) — общая

- Здесь лежат **все объекты и массивы** (включая массивы примитивов).
- Управляется **Garbage Collector** (сборщик мусора).
- Задаётся `-Xms` (начальный размер) и `-Xmx` (максимальный).
- Делится на **поколения** (Generational GC) — потому что большинство объектов живут очень недолго.

```
        Heap
 ┌───────────────────────┬──────────────────┐
 │   Young Generation    │  Old Generation  │
 │ ┌──────┬─────┬─────┐  │    (Tenured)     │
 │ │ Eden │ S0  │ S1  │  │                  │
 │ └──────┴─────┴─────┘  │                  │
 └───────────────────────┴──────────────────┘
```

- **Young Generation**: Eden + два Survivor (S0, S1).
  - Новые объекты создаются в **Eden**.
  - **Minor GC** копирует выживших в один из Survivor, затем между ними.
  - Объект, переживший несколько сборок, повышается (**promotion**) в Old.
- **Old Generation (Tenured)**: долгоживущие объекты. **Major/Full GC** — реже, но дороже.
- **TLAB** (Thread Local Allocation Buffer) — каждый поток получает кусочек Eden для быстрого выделения памяти **без блокировок**.
- **String Pool** (с Java 7) находится **в куче**.

Аналогия с поколениями: в студенческой общаге большинство жильцов — «молодые» (пришли и ушли), а «старики» (деканы, комендант) живут годами. Нет смысла каждую минуту проверять комнаты стариков — проверяем в основном молодёжь. Так GC реже заходит в Old.

### 4.3 Metaspace (Java 8+)

- Заменил **PermGen** (Java 7 и раньше).
- Хранит **метаданные классов**: структура класса, байт-код методов, vtable, статические поля, Runtime Constant Pool.
- Выделяется из **нативной** памяти, а не из кучи JVM → при утечке классов (частый кейс с прокси/ClassLoader) можно получить `OutOfMemoryError: Metaspace`.
- Ограничивается `-XX:MaxMetaspaceSize`. По умолчанию растёт динамически.

**PermGen vs Metaspace:**

| Критерий | PermGen (≤ Java 7) | Metaspace (Java 8+) |
|---|---|---|
| Где | Внутри кучи JVM | В нативной памяти |
| Размер | Фиксированный (`-XX:MaxPermSize`) | Динамический |
| Ошибка | `OutOfMemoryError: PermGen space` | `OutOfMemoryError: Metaspace` |
| String Pool | В PermGen | В Heap (с Java 7) |

### 4.4 String Pool

**String Pool** (пул строк) — специальная область, где хранятся **строковые литералы**, чтобы не создавать дубликаты.

```java
String a = "hello";
String b = "hello";
String c = new String("hello");

System.out.println(a == b);      // true  — оба из пула, один объект
System.out.println(a == c);      // false — c создан через new, отдельный объект
System.out.println(a.equals(c)); // true  — одинаковое содержимое
```

- До Java 7 пул жил в PermGen, с Java 7 — **в куче**.
- Метод `intern()` возвращает строку из пула.

### 4.5 Прочие области

- **PC Register** — на каждый поток, хранит адрес текущей исполняемой инструкции байт-кода.
- **Native Method Stack** — стек для нативных (JNI) методов, написанных на C/C++.
- **Code Cache** — скомпилированный JIT-код.
- **Direct Memory** — off-heap буферы (`ByteBuffer.allocateDirect`), задаётся `-XX:MaxDirectMemorySize`. Быстрее для I/O, но не управляется обычным GC.

### 4.6 Что где лежит — большая сводная таблица

| Данные | Где хранится |
|---|---|
| Локальный примитив | Stack (во фрейме) |
| Локальная ссылка | Stack (во фрейме) |
| Сам объект | Heap |
| Поля объекта | Heap (внутри объекта) |
| Статическое поле (ссылка/примитив) | Metaspace |
| Объект, на который ссылается static | Heap |
| String-литерал | String Pool (Heap) |
| Байт-код метода | Metaspace |
| Константы времени компиляции | Runtime Constant Pool |
| JIT-машинный код | Code Cache |
| Прямой ByteBuffer | Direct Memory (off-heap) |

> **Тонкость, на которой валятся:** статические **ссылки** лежат в Metaspace, но **объекты**, на которые они указывают, — в Heap. Статика хранит только ссылку (адрес), а тело объекта всегда в куче.

### 4.7 Флаги размера памяти

| Флаг | Что задаёт | Пример |
|---|---|---|
| `-Xss` | Размер стека потока | `-Xss1m` |
| `-Xms` | Начальный размер кучи | `-Xms512m` |
| `-Xmx` | Максимальный размер кучи | `-Xmx2g` |
| `-Xmn` | Размер Young Generation | `-Xmn512m` |
| `-XX:MaxMetaspaceSize` | Максимум Metaspace | `-XX:MaxMetaspaceSize=256m` |
| `-XX:MaxDirectMemorySize` | Максимум direct-памяти | `-XX:MaxDirectMemorySize=128m` |
| `-XX:ReservedCodeCacheSize` | Размер Code Cache | `-XX:ReservedCodeCacheSize=256m` |

### 4.8 Типичные ошибки раздела

- **Ошибка:** считать, что объекты хранятся в стеке. В стеке — только локальные переменные и ссылки.
- **Ошибка:** думать, что Metaspace — часть кучи. Нет, это нативная память.
- **Ошибка:** путать `StackOverflowError` (стек) и `OutOfMemoryError` (куча/Metaspace).
- **Ошибка:** думать, что String Pool всегда был в куче. До Java 7 — в PermGen.

### 4.9 Часто спрашивают на собеседовании

**Вопрос:** Какие области памяти поток-локальные, а какие общие?
**Ответ:** Локальные: Stack, PC Register, Native Method Stack. Общие: Heap, Metaspace, Code Cache, Direct Memory.

**Вопрос:** Зачем деление кучи на поколения?
**Ответ:** Большинство объектов умирают молодыми. Разделение позволяет быстро чистить Young (Minor GC) и редко трогать Old, экономя время.

**Вопрос:** Что такое TLAB?
**Ответ:** Thread Local Allocation Buffer — кусочек Eden у каждого потока для аллокации без блокировок.

**Вопрос:** Где хранятся статические переменные?
**Ответ:** Ссылки/примитивы — в Metaspace, объекты, на которые они ссылаются, — в Heap.

**Вопрос:** Чем Metaspace отличается от PermGen?
**Ответ:** Metaspace в нативной памяти и динамически растёт, PermGen был в куче с фиксированным размером.

## 5. Пакеты

### 5.1 Что такое пакет

**Пакет** — это одновременно:
1. **пространство имён** (логическая группировка классов);
2. **физическая иерархия папок** на диске.

```java
package com.company.project.service;

public class UserService {
    // ...
}
```

Файл должен лежать в `com/company/project/service/UserService.java`.

### 5.2 Зачем нужны пакеты (4 причины)

1. **Разрешение конфликтов имён** — можно иметь два класса `User` в разных пакетах (`com.a.User` и `com.b.User`).
2. **Управление доступом** — `package-private` и `protected` опираются на границы пакета.
3. **Модульность и организация** — логическая структура проекта (слои: `controller`, `service`, `dao`).
4. **Поиск классов** — ClassLoader ищет класс по пути, соответствующему пакету.

### 5.3 Правила именования пакетов

| Правило | Пример |
|---|---|
| **Реверс домена** | `com.company.project` |
| Только **строчные** буквы | `com.example` (не `Com.Example`) |
| Разделитель — точка | `com.company.util` |
| Нет дефисов и спецсимволов | `my-company.com` → `com.my_company` |
| Коллизия с ключевым словом → подчёркивание | `com.company._new` |
| Не занимать `java.*`, `javax.*` | свои имена |
| Осмысленные сегменты | `com.shop.order`, а не `com.shop.a.b` |

Аналогия с реверсом домена: домен `google.com` → пакет `com.google`. Так весь мир получает уникальные имена, не сговариваясь: у каждой компании свой домен.

### 5.4 package-private (доступ на уровне пакета)

Если у класса/метода/поля **нет модификатора доступа**, он виден **только внутри своего пакета**. Это называют **package-private** или **default access**.

```java
package com.example;

class Helper {          // package-private класс
    void doWork() {}    // package-private метод
}
```

### 5.5 Импорт и полные имена

```java
import java.util.List;            // обычный импорт
import java.util.*;               // wildcard (все классы пакета)
import static java.lang.Math.PI;  // статический импорт (константы/методы)

// полное имя без импорта
java.util.List<String> list = new java.util.ArrayList<>();
```

> Импорт **не** влияет на производительность и не «подключает» код — это лишь удобство записи имён.

### 5.6 Типичные ошибки раздела

- **Ошибка:** `import` не добавляет классы в проект — если класс не в classpath, импорт не поможет.
- **Ошибка:** пакет не соответствует структуре папок → `NoClassDefFoundError`.
- **Ошибка:** заглавные буквы в пакете (стилистически неверно, хотя технически компилируется).
- **Ошибка:** использовать дефис в имени пакета (не компилируется).

### 5.7 Часто спрашивают на собеседовании

**Вопрос:** Зачем нужны пакеты? Назови 4 причины.
**Ответ:** Конфликты имён, управление доступом, модульность/организация, поиск классов.

**Вопрос:** Что такое package-private?
**Ответ:** Доступ по умолчанию (без модификатора) — видно только внутри того же пакета.

**Вопрос:** Что делать, если в домене дефис?
**Ответ:** Заменить на подчёркивание: `my-company.com` → `com.my_company`.

## 6. Примитивные vs ссылочные типы

### 6.1 Восемь примитивов и их размеры

| Тип | Размер | Диапазон / значение | Литерал-пример |
|---|---|---|---|
| `byte` | 1 байт (8 бит) | -128 … 127 | `byte b = 100;` |
| `short` | 2 байта | -32 768 … 32 767 | `short s = 1000;` |
| `int` | 4 байта | ≈ -2.1 млрд … 2.1 млрд | `int i = 42;` |
| `long` | 8 байт | очень большой | `long l = 42L;` |
| `float` | 4 байта | 32-битное дробное | `float f = 3.14f;` |
| `double` | 8 байт | 64-битное дробное | `double d = 3.14;` |
| `char` | 2 байта | 0 … 65535 (UTF-16) | `char c = 'A';` |
| `boolean` | зависит от JVM (обычно 1 байт в массиве) | `true` / `false` | `boolean ok = true;` |

> `char` — **беззнаковый** 16-битный, хранит символ в кодировке UTF-16.

### 6.2 Что такое ссылочный тип

**Ссылочный тип** — это тип, значение которого **ссылка (адрес)** на объект в куче. К ссылочным относятся: все классы, интерфейсы, массивы, `String`, обёртки, перечисления.

```java
int a = 10;                 // примитив: в переменной само значение
String s = "hello";         // ссылка: в переменной адрес объекта
Object o = new Object();    // ссылка на новый объект
int[] arr = {1, 2, 3};      // ссылка на массив (объект)
```

### 6.3 Таблица отличий

| Критерий | Примитивы | Ссылочные типы |
|---|---|---|
| Что это | Атомарное значение | Ссылка на объект |
| Где хранится | Stack (локальные) / внутри объекта (поля) | Объект — Heap, ссылка — Stack/поле |
| Размер | Фиксированный | Ссылка фиксирована, объект — динамический |
| Значение по умолчанию | `0` / `false` / `'\u0000'` | `null` |
| Методы | Нет | Есть |
| Сравнение `==` | По значению | По ссылке (адресу) |
| Может быть `null` | Нет | Да |
| Наследование | Нет | Да |
| Generics | Нельзя | Можно |

### 6.4 `==` для примитивов и объектов

```java
int x = 5, y = 5;
System.out.println(x == y);            // true — значения равны

String s1 = new String("hi");
String s2 = new String("hi");
System.out.println(s1 == s2);          // false — разные объекты
System.out.println(s1.equals(s2));     // true — содержимое одинаковое
```

**Правило:** для объектов `==` сравнивает **адреса**, а `.equals()` — **содержимое** (если `equals` переопределён).

### 6.5 Значения по умолчанию

```java
public class Defaults {
    int i;          // 0
    boolean b;      // false
    double d;       // 0.0
    char c;         // '\u0000'
    String s;       // null
    int[] arr;      // null

    public static void main(String[] args) {
        Defaults o = new Defaults();
        System.out.println(o.i);     // 0
        System.out.println(o.b);     // false
        System.out.println(o.d);     // 0.0
        System.out.println((int) o.c); // 0
        System.out.println(o.s);     // null
        System.out.println(o.arr);   // null
    }
}
```

> **Важно:** локальные переменные **не инициализируются** по умолчанию. Их нужно задать явно, иначе ошибка компиляции. Значения по умолчанию действуют только для полей класса.

### 6.6 Boxing (упаковка)

Примитивы нельзя использовать в generics и некоторых API, поэтому есть **классы-обёртки**:

| Примитив | Обёртка |
|---|---|
| `byte` | `Byte` |
| `short` | `Short` |
| `int` | `Integer` |
| `long` | `Long` |
| `float` | `Float` |
| `double` | `Double` |
| `char` | `Character` |
| `boolean` | `Boolean` |

### 6.7 Типичные ошибки раздела

- **Ошибка:** сравнивать строки через `==` вместо `.equals()`.
- **Ошибка:** ожидать, что локальная переменная получит значение по умолчанию.
- **Ошибка:** пытаться положить `int` в `List<int>` — только `List<Integer>`.
- **Ошибка:** считать `boolean` строго 1 байтом — размер зависит от JVM.

### 6.8 Часто спрашивают на собеседовании

**Вопрос:** Перечисли 8 примитивов и их размеры.
**Ответ:** byte(1), short(2), int(4), long(8), float(4), double(8), char(2), boolean(зависит).

**Вопрос:** Чем ссылочный тип отличается от примитивного (5+ отличий)?
**Ответ:** Хранит адрес; объект в Heap; может быть null; есть методы; `==` по ссылке; участвует в наследовании; используется в generics.

**Вопрос:** Что сравнивает `==` для примитивов и объектов?
**Ответ:** Для примитивов — значение, для объектов — ссылку (адрес).

## 7. Модификаторы доступа и package-private

### 7.1 Четыре уровня доступа

| Модификатор | Класс | Пакет | Наследник | Весь мир |
|---|---|---|---|---|
| `private` | + | − | − | − |
| (default / package-private) | + | + | − | − |
| `protected` | + | + | + | − |
| `public` | + | + | + | + |

- **private** — только внутри самого класса.
- **default** (нет модификатора) = **package-private** — внутри пакета.
- **protected** — внутри пакета **и** в классах-наследниках (даже из других пакетов).
- **public** — везде.

### 7.2 Аналогия

Представь офис:
- `private` — личный ящик в столе (только ты).
- `default` — переговорная на этаже (только сотрудники этажа = пакета).
- `protected` — переговорная + доступ для «дочерних филиалов» (наследников).
- `public` — входная дверь на улицу (для всех).

### 7.3 Пример на все уровни

```java
package com.example.a;

public class Parent {
    private   int privateField = 1;    // только Parent
              int packageField = 2;    // пакет com.example.a
    protected int protectedField = 3;  // пакет + наследники
    public    int publicField = 4;     // везде

    private   void privateMethod() {}
              void packageMethod() {}
    protected void protectedMethod() {}
    public    void publicMethod() {}
}
```

```java
package com.example.a;

public class SamePackage {
    void test() {
        Parent p = new Parent();
        // p.privateField;   // ОШИБКА
        System.out.println(p.packageField);   // OK
        System.out.println(p.protectedField); // OK
        System.out.println(p.publicField);    // OK
    }
}
```

```java
package com.example.b;

import com.example.a.Parent;

public class Child extends Parent {
    void test() {
        // System.out.println(privateField);   // ОШИБКА
        // System.out.println(packageField);   // ОШИБКА (другой пакет)
        System.out.println(protectedField);    // OK — наследник
        System.out.println(publicField);       // OK
    }
}
```

### 7.4 Тонкость `protected` через ссылку наследника

`protected`-член доступен наследнику **в другом пакете**, но обращаться к нему можно только через ссылку типа **самого наследника** (или его подтипа), а не через ссылку родителя:

```java
package com.example.b;
import com.example.a.Parent;

public class Child extends Parent {
    void ok() {
        this.protectedField = 10;      // OK
        Child c = new Child();
        c.protectedField = 20;         // OK
    }

    void bad(Parent p) {
        // p.protectedField = 30;      // ОШИБКА: через ссылку Parent нельзя
    }
}
```

### 7.5 Верхнеуровневые классы

Верхнеуровневый класс может быть только **`public`** или **package-private**. `private` и `protected` для top-level классов запрещены. (У вложенных классов — можно все четыре.)

### 7.6 Правила при наследовании (переопределение)

При переопределении метода **нельзя сужать** уровень доступа:

```java
class A {
    protected void m() {}
}

class B extends A {
    // private void m() {}   // ОШИБКА компиляции: попытка ослабить доступ
    public void m() {}       // OK: расширять можно
}
```

Правило: `protected` → `public` — можно; `public` → `protected` — нельзя.

### 7.7 Типичные ошибки раздела

- **Ошибка:** сузить модификатор при переопределении (компилятор запретит).
- **Ошибка:** считать `protected` доступным везде «как public».
- **Ошибка:** обращаться к `protected` родителя из другого пакета через ссылку родителя.
- **Ошибка:** делать top-level класс `private`/`protected`.

### 7.8 Часто спрашивают на собеседовании

**Вопрос:** Что такое package-private?
**Ответ:** Уровень доступа по умолчанию — виден только внутри своего пакета.

**Вопрос:** Можно ли сузить доступ при переопределении?
**Ответ:** Нет, только расширить (`protected` → `public` можно, наоборот — нельзя).

**Вопрос:** Чем `protected` отличается от `default`?
**Ответ:** `protected` доступен ещё и наследникам из других пакетов (через ссылку наследника).

## 8. Почему `main` объявлен как `public static void`

### 8.1 Разбор сигнатуры

```java
public static void main(String[] args)
```

- **`public`** — JVM (launcher) вызывает метод извне класса, значит он должен быть доступен.
- **`static`** — метод вызывается **без создания объекта** класса.
- **`void`** — JVM не использует возвращаемое значение.
- **`main`** — имя, зашитое в спецификацию launcher'а.
- **`String[] args`** — аргументы командной строки.

### 8.2 Почему именно `static`

Когда программа запускается, **объекта ещё нет**. JVM не знает, как создавать твой класс (какой конструктор вызвать). Поэтому точка входа должна быть статической — чтобы её можно было вызвать, не создавая экземпляр.

### 8.3 Аргументы командной строки

```java
public class ArgsDemo {
    public static void main(String[] args) {
        System.out.println("Количество аргументов: " + args.length);
        for (String arg : args) {
            System.out.println("Аргумент: " + arg);
        }
    }
}
```

```bash
java ArgsDemo один два три
```

Вывод:

```
Количество аргументов: 3
Аргумент: один
Аргумент: два
Аргумент: три
```

### 8.4 Перегрузка main

Можно объявить **несколько** методов `main` с разными параметрами. Но JVM вызовет **только** `main(String[])`.

```java
public class Overload {
    public static void main(String[] args) {
        System.out.println("Главный main");
        main(42);
    }

    public static void main(int x) {
        System.out.println("Перегруженный main: " + x);
    }
}
```

Вывод:

```
Главный main
Перегруженный main: 42
```

### 8.5 Что будет, если убрать `static`

Компиляция пройдёт успешно, но при запуске:

```
Error: Main method is not static in class Main, please define the main method as:
   public static void main(String[] args)
```

Или (в зависимости от версии/ситуации) `NoSuchMethodError: main`.

### 8.6 Нюансы

- Порядок `static public` не важен: `static public void main(...)` тоже работает.
- До Java 5 можно было писать `String args[]` (C-стиль). Сейчас — плохой тон.
- `main` может быть `final`, `synchronized`, `strictfp` — сигнатура допускается, но не обязательна.
- Класс не обязан иметь `main`, если он не точка входа.
- `main` может быть `private` — тогда JVM его не найдёт (нужен `public`).

### 8.7 Новые фичи (Java 21+)

В **simple source files** (упрощённых исходных файлах, без объявления класса) разрешён более простой `void main()`:

```java
// Файл Hello.java (Java 21+ preview, Java 25 final)
void main() {
    System.out.println("Привет из simple source file!");
}
```

Запуск: `java Hello.java`. Компилятор сам генерирует обёртку. Это упрощает обучение и написание скриптов.

### 8.8 Типичные ошибки раздела

- **Ошибка:** забыть `static` → `NoSuchMethodError`/ошибка launcher'а.
- **Ошибка:** написать `main(String args)` (без массива) — JVM не распознает как точку входа.
- **Ошибка:** сделать `main` `private` — JVM не найдёт.
- **Ошибка:** ожидать, что `main(int)` будет точкой входа.

### 8.9 Часто спрашивают на собеседовании

**Вопрос:** Почему `main` именно `public static void`?
**Ответ:** public — чтобы JVM вызвала снаружи; static — чтобы вызвать без объекта; void — возврат не нужен; имя main и String[] — по спецификации launcher'а.

**Вопрос:** Что будет, если убрать `static`?
**Ответ:** Код скомпилируется, но при запуске JVM не найдёт корректную точку входа (NoSuchMethodError / ошибка launcher'а).

**Вопрос:** Можно ли перегрузить main?
**Ответ:** Да, но JVM вызовет именно `main(String[])`.

## 9. Массив: класс или примитив?

### 9.1 Массив — это объект

Массив — **объект** (ссылочный тип), но особый:

- Создаётся через `new`, лежит в **Heap**.
- Имеет поле **`length`** (не метод!).
- Наследуется от `Object`, но **не имеет** собственного `.java`-файла. JVM генерирует класс массива на лету.
- Реализует интерфейсы `Cloneable` и `Serializable`.
- Длина **фиксирована** при создании; массив **неизменяем по размеру**, но **изменяем по содержимому**.
- Может быть `null`, может быть многомерным (массив массивов).

### 9.2 Имена классов массивов

JVM генерирует имена в специальной нотации:

| Тип массива | Имя класса |
|---|---|
| `int[]` | `[I` |
| `long[]` | `[J` |
| `double[]` | `[D` |
| `byte[]` | `[B` |
| `boolean[]` | `[Z` |
| `char[]` | `[C` |
| `String[]` | `[Ljava.lang.String;` |
| `Object[]` | `[Ljava.lang.Object;` |
| `int[][]` | `[[I` |

```java
public class ArrayClassDemo {
    public static void main(String[] args) {
        int[] ints = new int[3];
        String[] strings = new String[3];
        int[][] matrix = new int[2][2];

        System.out.println(ints.getClass().getName());      // [I
        System.out.println(strings.getClass().getName());   // [Ljava.lang.String;
        System.out.println(matrix.getClass().getName());    // [[I
        System.out.println(ints instanceof Object);         // true
    }
}
```

### 9.3 `length` — поле, не метод

```java
int[] arr = {1, 2, 3};
System.out.println(arr.length);     // 3
// System.out.println(arr.length()); // ОШИБКА: length — поле, а не метод
System.out.println("abc".length());   // 3 — у String это МЕТОД length()
```

> Запомни: у массива — **поле** `length`, у `String` — **метод** `length()`. Классический вопрос-ловушка.

### 9.4 Ковариантность массивов и `ArrayStoreException`

Массивы **ковариантны**: `String[]` является подтипом `Object[]`.

```java
Object[] arr = new String[3];   // компилируется
arr[0] = "ok";                  // OK
arr[1] = 42;                    // ArrayStoreException в рантайме!
```

Почему: компилятор видит `Object[]` и разрешает положить `Integer`. Но в рантайме JVM помнит, что реально это `String[]`, и на попытке сохранить `Integer` бросает `ArrayStoreException`.

Аналогия: тебе выдали коробку с надписью «для яблок» (`Object[]`), но внутри она на самом деле предназначена только для красных яблок (`String[]`). Положить туда апельсин (`Integer`) система не даст.

### 9.5 Многомерные массивы

Java не имеет «настоящих» многомерных массивов — это **массив массивов** (зубчатый/jagged).

```java
int[][] grid = new int[3][4];   // 3 строки по 4 столбца
int[][] jagged = new int[3][];  // строки разной длины
jagged[0] = new int[]{1, 2};
jagged[1] = new int[]{3, 4, 5};
jagged[2] = new int[]{6};

for (int[] row : jagged) {
    for (int v : row) System.out.print(v + " ");
    System.out.println();
}
// 1 2
// 3 4 5
// 6
```

### 9.6 Полезные методы `Arrays` и `System.arraycopy`

```java
import java.util.Arrays;

int[] a = {3, 1, 2};
Arrays.sort(a);                              // [1, 2, 3]
System.out.println(Arrays.toString(a));      // [1, 2, 3]

int[] copy = Arrays.copyOf(a, 5);            // [1, 2, 3, 0, 0] (дополняет нулями)
int[] range = Arrays.copyOfRange(a, 1, 3);   // [2, 3]

System.out.println(Arrays.equals(a, copy));  // false
System.out.println(Arrays.binarySearch(a, 2)); // 1 (индекс)

int[] dest = new int[5];
System.arraycopy(a, 0, dest, 1, 3);          // копирует 3 элемента в dest[1..3]
System.out.println(Arrays.toString(dest));   // [0, 1, 2, 3, 0]

System.out.println(Arrays.asList("a", "b")); // [a, b]
```

| Метод | Что делает |
|---|---|
| `Arrays.sort` | Сортирует (dual-pivot quicksort для примитивов, TimSort для объектов) |
| `Arrays.toString` | Строковое представление |
| `Arrays.copyOf` | Копия с новой длиной |
| `Arrays.copyOfRange` | Копия диапазона |
| `Arrays.equals` | Сравнение содержимого |
| `Arrays.fill` | Заполнение значением |
| `Arrays.binarySearch` | Бинарный поиск (массив должен быть отсортирован) |
| `Arrays.asList` | Фиксированный список-обёртка |
| `Arrays.stream` | Поток из массива |
| `System.arraycopy` | Быстрое копирование (нативный метод) |

> `Arrays.asList` возвращает список **фиксированного размера**: `add`/`remove` бросят `UnsupportedOperationException`, но `set` работает.

### 9.7 Типичные ошибки раздела

- **Ошибка:** писать `arr.length()` вместо `arr.length`.
- **Ошибка:** путать `String.length()` (метод) и массив `.length` (поле).
- **Ошибка:** ждать `ArrayStoreException` на этапе компиляции — он только в рантайме.
- **Ошибка:** пытаться изменить размер массива — только создать новый.
- **Ошибка:** думать, что `Arrays.asList` изменяемый по размеру.

### 9.8 Часто спрашивают на собеседовании

**Вопрос:** Массив — класс или примитив? Докажи.
**Ответ:** Объект. У него есть `.getClass()`, `instanceof Object` = true, `length`, он наследует Object, реализует Cloneable/Serializable. Но собственного `.java`-класса нет — JVM генерирует (`[I`, `[Ljava.lang.String;`).

**Вопрос:** Что такое ковариантность массивов?
**Ответ:** `String[]` — подтип `Object[]`. Поэтому можно положить `Integer` в `Object[]`, ссылающийся на `String[]`, но в рантайме — `ArrayStoreException`.

**Вопрос:** Чем `.length` массива отличается от `length()` строки?
**Ответ:** У массива `length` — поле; у String — метод `length()`.

## 10. Классы-обёртки и Integer cache

### 10.1 Что такое обёртки

Обёртки — классы, «оборачивающие» примитивы в объекты:

`Byte`, `Short`, `Integer`, `Long`, `Float`, `Double`, `Character`, `Boolean`.

Особенности:
- Все — **`final`** и **неизменяемые** (immutable).
- Наследуют `Number` (кроме `Character` и `Boolean`).
- Нужны для generics, коллекций, `null`-значений, утилитных методов (`Integer.parseInt`).

### 10.2 Integer cache: диапазон -128..127

JVM **кэширует** объекты `Integer` для значений от **-128 до 127**, чтобы не создавать их заново.

```java
Integer a = 100, b = 100;
System.out.println(a == b);        // true  — оба из кэша (один объект)

Integer c = 1000, d = 1000;
System.out.println(c == d);        // false — вне кэша, разные объекты
System.out.println(c.equals(d));   // true  — по значению
```

Верхнюю границу кэша можно расширить флагом `-XX:AutoBoxCacheMax=2000` (диапазон станет -128..2000). Нижняя граница **всегда** -128.

### 10.3 Аналогичный кэш у других обёрток

| Обёртка | Диапазон кэша |
|---|---|
| `Integer` | -128 … 127 (настраивается) |
| `Long` | -128 … 127 (фиксирован) |
| `Short` | -128 … 127 (фиксирован) |
| `Byte` | -128 … 127 (все значения) |
| `Character` | 0 … 127 (фиксирован) |
| `Boolean` | `TRUE`, `FALSE` (два объекта) |

> У `Float`/`Double` кэша **нет** — `Float a = 1.0f, b = 1.0f; a == b` → `false`.

### 10.4 Почему кэш именно такой

Значения -128..127 — самые частые в типичном коде (счётчики, флаги, индексы). Кэширование экономит память и время. Это **компромисс** между пользой и памятью: кэшировать все `int` было бы расточительно.

### 10.5 `new Integer` и `==`

```java
Integer a = new Integer(10);   // устаревший конструктор, создаёт НОВЫЙ объект
Integer b = new Integer(10);
System.out.println(a == b);    // false — всегда, даже для -128..127
System.out.println(a.equals(b)); // true
```

> Конструкторы `new Integer(...)` **deprecated** с Java 9. Используй `Integer.valueOf(...)`.

### 10.6 Обёртка vs примитив: `==` и NPE

```java
Integer boxed = 100;
int primitive = 100;
System.out.println(boxed == primitive);   // true — boxed распаковывается

Integer nullBoxed = null;
// int x = nullBoxed;   // NullPointerException при распаковке
```

Правило: если в `==` участвуют обёртка и примитив, обёртка **распаковывается**, что может дать `NPE`.

### 10.7 Практический пример-ловушка

```java
Integer a = 127, b = 127, c = 128, d = 128;
System.out.println(a == b);   // true
System.out.println(c == d);   // false
```

### 10.8 Типичные ошибки раздела

- **Ошибка:** сравнивать обёртки через `==` вместо `.equals()`.
- **Ошибка:** считать, что `1000 == 1000` для `Integer` даст `true`.
- **Ошибка:** распаковывать `null`-обёртку → `NPE`.
- **Ошибка:** использовать `new Integer(...)` (deprecated).

### 10.9 Часто спрашивают на собеседовании

**Вопрос:** Что такое Integer cache? В каком диапазоне?
**Ответ:** Кэш объектов Integer от -128 до 127 (верхняя граница настраивается `-XX:AutoBoxCacheMax`). Обеспечивает `==` = true внутри диапазона.

**Вопрос:** Что выведет `Integer a=1000,b=1000; a==b`?
**Ответ:** `false` — значения вне кэша, разные объекты. А `.equals()` → `true`.

**Вопрос:** Зачем нужны обёртки?
**Ответ:** Для generics/коллекций (примитивы туда нельзя), `null`, утилитных методов, единообразия.

## 11. Autoboxing и unboxing

### 11.1 Что это

- **Autoboxing** — автоматическая упаковка примитива в обёртку.
- **Unboxing** — автоматическая распаковка обёртки в примитив.

```java
Integer i = 5;      // autoboxing:   компилятор вставит Integer.valueOf(5)
int x = i;          // unboxing:     компилятор вставит i.intValue()
```

### 11.2 Как реализовано под капотом

| Операция | Что генерирует компилятор |
|---|---|
| Autoboxing | `Integer.valueOf(x)` |
| Unboxing | `x.intValue()` (или `longValue`, `doubleValue` и т.д.) |

Именно поэтому `Integer i = 5;` внутри диапазона кэша даёт объект **из кэша**, а `Integer i = 1000;` — новый объект.

### 11.3 Ловушка с `null`

```java
Integer i = null;
int x = i;   // NullPointerException: i.intValue() на null
```

Это одна из самых частых ошибок в реальном коде: `Map<String,Integer>.get()` может вернуть `null`, а ты присваиваешь результат в `int`.

### 11.4 Autoboxing в коллекциях

```java
import java.util.*;

List<Integer> list = new ArrayList<>();
list.add(1);                 // autoboxing: add(Integer.valueOf(1))
int first = list.get(0);     // unboxing: list.get(0).intValue()

Map<String, Integer> map = new HashMap<>();
map.put("a", 10);            // autoboxing
map.put("a", map.getOrDefault("a", 0) + 1); // распаковка, сложение, упаковка
System.out.println(map);     // {a=11}
```

### 11.5 Ловушка с перегрузкой: `f(long)` vs `f(Integer)`

```java
public class OverloadBoxing {
    static void f(long x)    { System.out.println("f(long)"); }
    static void f(Integer x) { System.out.println("f(Integer)"); }

    public static void main(String[] args) {
        f(1);   // f(long) — расширение примитива ПРИОРИТЕТНЕЕ боксинга
    }
}
```

**Правило приоритета при разрешении перегрузки:**
1. Точное совпадение типа.
2. Расширение примитива (widening): `int` → `long` → `float` → `double`.
3. Autoboxing.
4. Varargs.

Поэтому для `f(1)` выбирается `f(long)`: расширение `int→long` стоит раньше упаковки.

### 11.6 Производительность: боксы в цикле

```java
// ПЛОХО: каждая итерация создаёт новый Long (вне кэша) + упаковка/распаковка
Long sum = 0L;
for (long i = 0; i < 1_000_000; i++) {
    sum += i;   // sum = Long.valueOf(sum.longValue() + i)
}

// ХОРОШО: примитив
long sum2 = 0L;
for (long i = 0; i < 1_000_000; i++) {
    sum2 += i;
}
```

Первый вариант создаёт сотни тысяч объектов `Long` → нагрузка на GC. В горячем коде избегай обёрток.

### 11.7 Тернарный оператор и unboxing

```java
Integer a = null;
Integer b = 5;
// int c = true ? a : b;   // NullPointerException: ветвь распаковывается
```

Тернарный оператор с `Integer` и `int` может привести к неожиданной распаковке.

### 11.8 Сводная таблица ловушек

| Ситуация | Результат |
|---|---|
| `Integer i = null; int x = i;` | `NullPointerException` |
| `f(1)` при `f(long)` и `f(Integer)` | вызывается `f(long)` |
| `Long sum = 0L; sum += i;` в цикле | Лишние аллокации |
| `true ? nullInteger : intValue` | Возможен `NPE` |
| `Integer a = 1000, b = 1000; a == b` | `false` |
| `Integer a = 100, b = 100; a == b` | `true` |

### 11.9 Типичные ошибки раздела

- **Ошибка:** забыть про `null` при unboxing.
- **Ошибка:** использовать обёртки в горячих циклах.
- **Ошибка:** путать приоритет перегрузки (ожидать `f(Integer)`, получить `f(long)`).
- **Ошибка:** сравнивать обёртки через `==`.

### 11.10 Часто спрашивают на собеседовании

**Вопрос:** Как реализованы autoboxing/unboxing?
**Ответ:** Компилятор вставляет `valueOf(...)` и `xxxValue()`. Поэтому работает кэш Integer.

**Вопрос:** Приведи ловушку с `null`.
**Ответ:** `Integer i = null; int x = i;` → `NullPointerException` при `i.intValue()`.

**Вопрос:** Какой метод вызовется: `f(long)` или `f(Integer)` для `f(1)`?
**Ответ:** `f(long)` — расширение примитива приоритетнее боксинга.

## 12. Нововведения Java 8 (подробно) и обзор Java 9–21

### 12.1 Java 8 — почему это переломная версия

Java 8 (2014) — самая значимая версия после Java 5. Она принесла **функциональный стиль**, и именно её фичи спрашивают чаще всего.

### 12.2 Лямбда-выражения

**Лямбда** — короткая запись анонимной реализации функционального интерфейса.

```java
// До Java 8: анонимный класс
Runnable r1 = new Runnable() {
    @Override
    public void run() {
        System.out.println("Старый способ");
    }
};

// Java 8: лямбда
Runnable r2 = () -> System.out.println("Новый способ");

r1.run(); // Старый способ
r2.run(); // Новый способ
```

Аналогия: лямбда — это как вместо целой анкеты «ФИО, должность, подпись» написать короткую записку «сделай вот это».

### 12.3 Функциональные интерфейсы

**Функциональный интерфейс** — интерфейс ровно с **одним абстрактным методом** (SAM). Помечается `@FunctionalInterface` (необязательно, но полезно — компилятор проверит).

```java
@FunctionalInterface
interface Calculator {
    int apply(int a, int b);
}

public class LambdaDemo {
    public static void main(String[] args) {
        Calculator add = (a, b) -> a + b;
        Calculator mul = (a, b) -> a * b;
        System.out.println(add.apply(2, 3)); // 5
        System.out.println(mul.apply(2, 3)); // 6
    }
}
```

### 12.4 Встроенные функциональные интерфейсы (`java.util.function`)

| Интерфейс | Сигнатура | Смысл |
|---|---|---|
| `Function<T,R>` | `R apply(T)` | Преобразование |
| `BiFunction<T,U,R>` | `R apply(T,U)` | Преобразование двух |
| `Consumer<T>` | `void accept(T)` | Потребитель (ничего не возвращает) |
| `Supplier<T>` | `T get()` | Поставщик значения |
| `Predicate<T>` | `boolean test(T)` | Проверка условия |
| `UnaryOperator<T>` | `T apply(T)` | Унарная операция |
| `BinaryOperator<T>` | `T apply(T,T)` | Бинарная операция |
| `Runnable` | `void run()` | Действие без аргументов |

```java
import java.util.function.*;

Function<String, Integer> len = String::length;
Consumer<String> print = System.out::println;
Supplier<String> hello = () -> "hello";
Predicate<Integer> isEven = n -> n % 2 == 0;

System.out.println(len.apply("abcd")); // 4
print.accept("hi");                    // hi
System.out.println(hello.get());       // hello
System.out.println(isEven.test(4));    // true
```

### 12.5 Метод-ссылки

Ссылка на метод — ещё более короткая запись лямбды: `Класс::метод`.

| Вид | Пример | Эквивалент лямбды |
|---|---|---|
| Статический метод | `Integer::parseInt` | `s -> Integer.parseInt(s)` |
| Метод объекта | `System.out::println` | `x -> System.out.println(x)` |
| Метод конкретного объекта | `str::toUpperCase` | `() -> str.toUpperCase()` |
| Конструктор | `ArrayList::new` | `() -> new ArrayList<>()` |

### 12.6 Stream API

**Stream** — декларативная обработка коллекций: описываем **что** сделать, а не **как**.

```java
import java.util.*;
import java.util.stream.*;

List<String> names = Arrays.asList("Аня", "Борис", "Алиса", "Вова", "Богдан");

List<String> result = names.stream()
        .filter(n -> n.startsWith("Б"))     // промежуточная операция
        .map(String::toUpperCase)           // промежуточная
        .sorted()                           // промежуточная
        .collect(Collectors.toList());      // терминальная

System.out.println(result); // [БОГДАН, БОРИС]
```

Ключевое:
- **Промежуточные** операции (`filter`, `map`, `sorted`, `distinct`, `limit`, `flatMap`) ленивы — не выполняются, пока нет терминальной.
- **Терминальные** (`collect`, `forEach`, `reduce`, `count`, `anyMatch`, `findFirst`) запускают обработку.
- Поток можно пройти **один раз**; повторно использовать нельзя.

```java
long count = names.stream().filter(n -> n.length() > 3).count();
System.out.println(count); // 5
```

### 12.7 Default и static методы в интерфейсах

До Java 8 интерфейсы не могли иметь реализацию. Теперь могут — с `default`:

```java
interface Greeting {
    void sayHello();

    default void sayBye() {
        System.out.println("Пока!");
    }

    static Greeting english() {
        return () -> System.out.println("Hello!");
    }
}

class Person implements Greeting {
    public void sayHello() { System.out.println("Привет!"); }
}

public class Demo {
    public static void main(String[] args) {
        Person p = new Person();
        p.sayHello();          // Привет!
        p.sayBye();            // Пока!
        Greeting.english().sayHello(); // Hello!
    }
}
```

Зачем: можно **добавлять методы в интерфейсы**, не ломая существующие реализации (например, `Iterable.forEach`).

### 12.8 Optional

**Optional** — контейнер, который может содержать значение или быть пустым. Помогает явно обрабатывать отсутствие значения вместо `null`.

```java
import java.util.Optional;

Optional<String> opt = Optional.of("значение");
System.out.println(opt.isPresent());              // true
System.out.println(opt.orElse("по умолчанию"));   // значение

Optional<String> empty = Optional.empty();
System.out.println(empty.orElse("по умолчанию")); // по умолчанию

// Цепочка
Optional.of("hello")
        .map(String::toUpperCase)
        .ifPresent(System.out::println);          // HELLO
```

> `Optional.of(null)` бросит `NullPointerException`; для nullable используй `Optional.ofNullable`.

### 12.9 Новая дата и время (`java.time`)

До Java 8 была `Date`/`Calendar` — изменяемые и с багами. Теперь есть **иммутабельный** и **потокобезопасный** API:

```java
import java.time.*;
import java.time.format.DateTimeFormatter;

LocalDate date = LocalDate.of(2026, 10, 1);
LocalTime time = LocalTime.of(14, 30);
LocalDateTime dt = LocalDateTime.of(date, time);

System.out.println(date);                 // 2026-10-01
System.out.println(date.plusDays(5));     // 2026-10-06
System.out.println(dt.format(DateTimeFormatter.ISO_LOCAL_DATE_TIME));

Duration d = Duration.ofHours(2);         // длительность (время)
Period p = Period.ofDays(10);             // период (даты)
ZonedDateTime zoned = ZonedDateTime.now(ZoneId.of("Europe/Moscow"));
```

### 12.10 Metaspace вместо PermGen

В Java 8 удалили PermGen и ввели Metaspace (см. раздел 4.3). Это тоже «нововведение» Java 8, которое спрашивают вместе с памятью.

- **`CompletableFuture`** — асинхронные цепочки, замена колбэков.

CompletableFuture.supplyAsync(() -> "мир")

## Шпаргалка

### Платформа
- **JDK ⊃ JRE ⊃ JVM**; JVM — спецификация, HotSpot — реализация.
- JRE = JVM + библиотека классов (для запуска); JDK = JRE + инструменты (для разработки).
- WORA: один байт-код — любая ОС с JVM.
- Реализации JVM: HotSpot, OpenJ9, GraalVM, ART.

### Компиляция и запуск
- `javac Main.java` → `Main.class`; `java Main` — имя **класса**, не файла.
- `javac -d . com/example/Main.java`; запуск `java com.example.Main` из корня.
- `java Main.java` (Java 11+) — компиляция в память без `.class`.
- `-cp` — classpath, `-d` — куда класть классы.
- `ClassNotFoundException` (checked, явный поиск) ≠ `NoClassDefFoundError` (Error, класс пропал) ≠ `NoSuchMethodError` (нет метода).

### JIT
- Интерпретатор быстрый на старте, JIT ускоряет hot spots.
- Профилирование → компиляция → Code Cache → подмена.
- C1 быстрый (прогрев), C2 умный (пик); Tiered = оба.
- Оптимизации: inlining, loop unrolling, Escape Analysis, scalar replacement, devirtualization.
- Деоптимизация — откат при нарушении предположений.
- GraalVM Native Image — AOT (быстрый старт, без динамики).

### Память
- Поток-локальные: Stack, PC Register, Native Method Stack.
- Общие: Heap, Metaspace, Code Cache, Direct Memory.
- Stack: фреймы, локальные примитивы/ссылки, LIFO, `-Xss`, `StackOverflowError`.
- Heap: объекты и массивы, `-Xms`/`-Xmx`, Young (Eden+S0+S1) и Old, TLAB.
- Metaspace: метаданные классов, нативная память, `-XX:MaxMetaspaceSize` (заменил PermGen).
- String Pool — в Heap с Java 7 (до — в PermGen).
- Static-ссылка — Metaspace, объект по ней — Heap.
- Direct Memory: `ByteBuffer.allocateDirect`, off-heap, `-XX:MaxDirectMemorySize`.

### Язык
- 8 примитивов: byte(1), short(2), int(4), long(8), float(4), double(8), char(2), boolean(зависит).
- Примитивы — значения; ссылки — адреса; `==` — значение или ссылка; `.equals` — содержимое.
- Локальные переменные не имеют дефолтов; поля — имеют (`0`/`false`/`null`).
- Модификаторы: private < default(package-private) < protected < public.
- `protected` доступен наследникам из других пакетов (через ссылку наследника).
- Нельзя сужать доступ при переопределении.
- Пакеты: реверс домена, строчные, `_` вместо дефиса.

### main и массивы
- `public static void main(String[] args)`: public — вызов извне, static — без объекта, void — без возврата.
- Без `static` — ошибка launcher'а / `NoSuchMethodError`.
- Java 21+ simple source files: `void main()`.
- Массив — объект: `.getClass()`, `instanceof Object`, поле `length`, Cloneable/Serializable.
- Классы массивов: `[I`, `[Ljava.lang.String;`, `[[I`.
- Ковариантность → `ArrayStoreException` в рантайме.
- `Arrays.*`, `System.arraycopy`; `Arrays.asList` — фиксированный размер.

### Обёртки и боксы
- Обёртки: final, immutable, наследуют Number (кроме Character/Boolean).
- Integer cache: -128..127 (верх настраивается `-XX:AutoBoxCacheMax`).
- `Float`/`Double` — без кэша.
- Autoboxing = `valueOf`, unboxing = `xxxValue()`.
- `null` при unboxing → `NPE`.
- `f(1)` при `f(long)`/`f(Integer)` → `f(long)`.
- В горячем коде избегать боксов.

### Java 8+
- Java 8: лямбды, Stream, default/static методы, Optional, java.time, Metaspace, CompletableFuture.
- Java 9: модули, `List.of`; Java 10: `var`; Java 11: `java File.java`.
- Java 14+: switch-выражения; Java 16: records; Java 17: sealed (LTS).
- Java 21: virtual threads, record patterns, pattern matching, SequencedCollection (LTS).

## Частые вопросы на собеседовании с короткими ответами

1. **Что такое JVM, JRE, JDK?** JVM исполняет байт-код; JRE = JVM + библиотеки; JDK = JRE + инструменты. JDK ⊃ JRE ⊃ JVM.
2. **JVM — спецификация или реализация?** Спецификация; реализации — HotSpot, OpenJ9, GraalVM.
3. **Что такое WORA?** Write Once, Run Anywhere — байт-код переносим между ОС.
4. **Зачем `-d` при компиляции?** Раскладывает `.class` по структуре пакета.
5. **Почему `java Main.class` — ошибка?** `java` принимает имя класса, не файл.
6. **Что делает `java Main.java`?** Компилирует исходник в память и запускает без `.class`.
7. **ClassNotFoundException vs NoClassDefFoundError?** Первое — checked при явном поиске; второе — Error, класс отсутствует/не инициализировался.
8. **Что такое JIT?** Компилятор «на лету»: hot spots → машинный код.
9. **Hot spots и Code Cache?** Часто исполняемый код и область для его скомпилированной версии.
10. **C1 vs C2?** C1 быстрый с базовыми оптимизациями, C2 медленный но агрессивный; Tiered использует оба.
11. **Escape Analysis?** Анализ, не убегает ли объект; если нет — на стек, без GC.
12. **Деоптимизация?** Откат оптимизации при нарушении предположений JIT.
13. **Области памяти JVM?** Stack, PC, Native Stack (локальные); Heap, Metaspace, Code Cache, Direct (общие).
14. **Что во фрейме стека?** Локальные примитивы, ссылки, операнд-стек, ссылка на пул констант.
15. **Зачем поколения кучи?** Большинство объектов молоды; Minor GC дешевле, Old трогают редко.
16. **TLAB?** Локальный буфер потока в Eden для аллокации без блокировок.
17. **Где String Pool?** В Heap с Java 7 (ранее PermGen).
18. **Metaspace vs PermGen?** Metaspace в нативной памяти и динамический; PermGen был в куче.
19. **Где статика?** Ссылки/примитивы — Metaspace; объекты — Heap.
20. **Что такое Runtime Constant Pool?** Пул констант класса, часть метаданных в Metaspace.
21. **Причины `OOM: Metaspace`?** Утечка классов/ClassLoader (прокси, динамическая генерация).
22. **Зачем пакеты?** Конфликты имён, доступ, модульность, поиск классов.
23. **Правила имён пакетов?** Реверс домена, строчные, `_` вместо дефиса.
24. **8 примитивов и размеры?** byte1, short2, int4, long8, float4, double8, char2, boolean(зависит).
25. **5 отличий ссылок от примитивов?** Адрес vs значение; Heap; null; методы; generics; наследование.
26. **`==` для примитивов/объектов?** Значение / ссылку.
27. **Модификаторы доступа?** private < default < protected < public.
28. **package-private?** Уровень по умолчанию — видно только в своём пакете.
29. **Можно сузить доступ при override?** Нет, только расширить.
30. **Почему main `public static void`?** public — вызов извне, static — без объекта, void — без возврата.
31. **Без `static` у main?** Код скомпилируется, но JVM не найдёт точку входа.
32. **Массив — класс или примитив?** Объект без `.java`-класса; имена `[I`, `[Ljava.lang.String;`.
33. **Ковариантность массивов?** `String[]` — подтип `Object[]`; запись чужого типа → `ArrayStoreException`.
34. **`.length` vs `.length()`?** У массива — поле; у String — метод.
35. **Зачем обёртки?** Generics, коллекции, null, утилитные методы.
36. **Integer cache?** -128..127; вне — разные объекты, `==` = false.
37. **Autoboxing/unboxing?** `valueOf`/`xxxValue`; ловушка — `NPE` при unboxing `null`.
38. **`f(long)` vs `f(Integer)` для `f(1)`?** `f(long)` — widening приоритетнее боксинга.
